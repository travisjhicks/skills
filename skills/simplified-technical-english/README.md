# simplified-technical-english

An [Agent Skill](https://agentskills.io) that rewrites technical
prose into a **controlled English for software**—a style built on the concepts
of ASD-STE100 Simplified Technical English, but deliberately its own thing. The
target reader is an engineer mid-task or a second-language reader who needs to
understand each sentence on the first pass; the target text is software prose:
documentation, instructions, reports, and text written by or for large language
models.

Use it when the goal is clearer technical prose, not conformance. The output
does **not** conform to ASD-STE100 and is not intended to: it skips the
standard's controlled dictionary and changes several of its rules. For
conformant text, apply the standard as written.

## Installing

Install this skill with the [`skills` CLI](https://github.com/vercel-labs/skills):

```bash
npx skills add travisjhicks/skills --skill simplified-technical-english
```

Add `-g` to install it for your user account instead of the current project, and
`-a claude-code` or `-a codex` to skip the agent prompt. See the
[repository README](../../README.md#installing) for other options.

## What it does

The rewrite applies the controlled-language core—one word per meaning, one
instruction per sentence, active voice, simple tenses only, 20-word
instruction and 25-word description sentence caps—plus rules the standard
doesn't have because aerospace manuals don't need them:

- **Three registers, not one.** Instruction (imperative, condition first),
  report (simple past, agent named—"I removed the import", never "the file
  was updated"), and description (conclusion first, one new subject per
  sentence). The report register is the big addition: software prose spends
  much of its length describing finished work.
- **Protected content.** Code, identifiers, paths, shell commands, quoted tool
  output, RFC-style normative keywords, and direct quotations are reproduced
  character for character. A banned word is often the payload—"already" in
  `EEXIST: file already exists` stays put.
- **A substitution list instead of a closed dictionary.** Common inflations
  (leverage, utilize, prior to, in order to, it is recommended that) map to
  plain replacements, including software slang: "blow away" → delete,
  "spin up" → start, "surface" → show.
- **Warnings restructured for software.** WARNING means unrecoverable loss
  (production data, a published package); CAUTION means recoverable local
  loss. The rewrite names exactly what disappears—"this is destructive" is
  not a warning.

The contract is strict: same facts, same claims, same certainty, same document
structure. Sentences change; nothing else does.

## How it's built

The rewrite runs in an **isolated subagent** with a clean context, so wording
from the surrounding session cannot bleed into the translation. The user's
text is fenced with a random boundary token generated by the operating system,
and everything inside the fence is treated as data—instructions embedded in
the input are rewritten as text, not obeyed. The skill is self-contained: the
full rule set is inline in `SKILL.md`, with no reference files to load.

## Usage

```text
/simplified-technical-english It should be noted that the config will need to be updated prior to deployment.
/simplified-technical-english docs/runbook.md
```

Or describe the goal: "rewrite this so a non-native reader gets it on the
first pass."

## Where it deviates from the standard

The deviations are deliberate and listed in full at the end of
[`SKILL.md`](SKILL.md): no closed dictionary, `check`/`test`/`report`/`request`
stay usable as verbs, the added report register, redefined WARNING/CAUTION,
dropped word-counting arithmetic, and a different set of surviving phrasal
verbs (check out, roll back, back up, log in, set up).
